# 제출 점검

아래 대회 정보는 사용자 제공 요약 기준이며 최신 공식 공지 확인이 필요하다.

## 공식 심사와 연결할 증거

1차는 기획 구체성·창의성·기술 완성도·성과 및 실용성·팀 구성 및 협업 각각 20점이다. 2차는 문제 전달·해결력, 기술·라이브 시연, 적용·확장성, 발표·팀워크 각각 25점이다.

문제 사례, 기존 대안과 차이, 실제 개발한 부분, 평가 결과, 역할 및 통합 기록을 개발 중부터 모은다. 단순 API 호출 외에 무엇을 직접 구현했는지 구체적으로 설명한다.

## 발표 PDF — 표지 제외 10페이지 이내

- [ ] 문제 정의 및 목표 사용자
- [ ] 해결 방안 및 주요 기능
- [ ] 활용 AI 기술 및 직접 개발 범위
- [ ] 개발 환경 및 기술 스택
- [ ] 팀원별 역할 분담
- [ ] 외부 자원 활용 내역 — 없으면 “해당 없음”
- [ ] 기대 효과 및 확장 가능성
- [ ] PDF 열림·글자·페이지 수 확인

## 시연 영상 — MP4, 2분 이내

- [ ] 실제 서비스 입력부터 결과 출력까지 촬영
- [ ] 핵심 기능과 AI의 기여 식별 가능
- [ ] 글자와 UI가 보임 — 1080p 이상 권장
- [ ] 길이·재생·음성 확인
- [ ] 슬라이드·디자인 시안만 보여주는 영상이 아님

## 소스코드 및 드라이브 제출

- [ ] 전체 소스와 README를 갖춘 Public GitHub 저장소
- [ ] README에 실제 설치·환경설정·실행 명령
- [ ] 새로운 환경에서 실행 절차 확인
- [ ] 키·토큰·개인정보·불필요한 데이터 포함 여부 확인
- [ ] 최종 커밋 해시 확정
- [ ] `뽀스와아이들_소스코드.txt`에 저장소 URL과 최종 커밋 해시 작성
- [ ] 로그아웃 상태에서 저장소와 해당 커밋 접근 확인
- [ ] 지정 드라이브에 PDF·MP4·소스코드 안내 파일 모두 제출
- [ ] 업로드 후 파일을 다시 열고 실제 제출 상태 확인
- [ ] 심사 종료까지 Public 유지
