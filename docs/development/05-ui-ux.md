## 3. 화면 구성

### 공통 헤더 / 푸터
- 헤더: 서비스 이름 "어른왕자", 인트로 다시 보기 · 지난 기록 링크
- 푸터: "게임 속 사건과 인물은 가상이며, 직업 정보는 직업백과를 근거로 합니다. 결과는 실제 진로 · 취업을 보장하지 않습니다."

### 화면 0: 인트로 (`/intro`, 선택)
> Unity 담당이 만든 React + Three.js 인트로(`career-intro-react-v001`)를 그대로 옮긴다. 직업 공간 3D 모델 71개를 24초 동안 이어 보여 준다. 화면 · 연출 · 문구는 원본을 유지하고 아래 항목만 더한다.

```
┌───────────────────────────────────┐
│ CAREER SPACES     A WORLD OF ...   │
│                                   │
│  가능성이        [3D 공간 · 카메라] │
│  펼쳐지는 공간.                     │
│                                   │
│  ┌ 준비 중: 12 / 71 ━━━━━░░░░░ ┐  │  ← 다 받으면 [인트로 재생 ↗]
│  └─────────────────────────────┘  │
│ [일시정지][다시 보기][소리][촬영][전체 화면] 00:12 / 00:24 │
│                          [건너뛰기] │
└───────────────────────────────────┘
```
- 언제: **처음 방문했을 때만** `/` 에서 `/intro` 로 보낸다. 본 기록(끝까지 봄 · 건너뜀)은 localStorage 에 남기고, 다음 방문부터는 바로 시작 화면을 보여 준다. 실패는 기록하지 않고 이번 방문(탭) 동안만 생략한다 (에셋이 나중에 배치되면 다시 보이도록). 헤더의 "인트로 다시 보기" 로 언제든 다시 볼 수 있다
- 재생: 모델 71개를 모두 받은 뒤 **[인트로 재생]** 을 눌러 시작한다 (소리는 Web Audio 로 만들기 때문에 사용자 클릭이 필요). 24초 뒤 검게 페이드되면 시작 화면으로 간다
- **[건너뛰기]** (원본에 없어 추가): 로딩 중 · 재생 중 언제든 누를 수 있다. 누르면 시작 화면으로 간다
- 실패: 에셋을 못 받거나 WebGL 을 쓸 수 없으면 토스트 "인트로를 불러오지 못해 시작 화면으로 이동해요." 를 띄우고 시작 화면으로 간다
- 에셋: `intro.json` + 모델 71개(약 238MB)는 저장소에 넣지 않고 백엔드 서버 `/intro-assets/` 에서만 받는다 (백엔드 기능 [BE15](features.md#1-백엔드-be)). **에셋 주소가 설정되지 않은 배포**(`VITE_INTRO_ASSET_BASE` · `VITE_API_BASE_URL` 모두 비어 있음)에서는 인트로를 띄우지 않고 바로 시작 화면을 보여 주며, 헤더의 "인트로 다시 보기" 도 숨긴다 주소 규칙은 [06 3절 환경변수](06-deployment.md#3-환경변수) `VITE_INTRO_ASSET_BASE`
- 키보드: 인트로 안에 초점이 있을 때 Space 일시정지 · R 다시 보기 · Esc 촬영 화면 해제 (원본 동작)
- 모션 줄이기: OS 의 `prefers-reduced-motion` 이 켜져 있으면 카메라를 고정하고 빛 효과를 끈다 (원본 동작, 장면 교체 · 페이드는 유지)
- 성능: 인트로 코드(Three.js 포함)는 따로 나눠 불러와 다른 화면 로딩에 섞이지 않게 한다. 화면을 떠나면 GPU 자원 · 소리 · 이벤트를 정리한다
- 관련 기능 #: FE11

### 화면 1: 시작 (`/`)
```
┌───────────────────────────────┐
│ 어른왕자                        │
│ 이름 [        ]  나이 [  ]      │
│ 지금 상황 [중학생 ▾]            │
│ 되고 싶은 직업이 있나요? (예)(아니오) │
│   └ 있으면: 직업 [        ]      │
│ ── 조금 더 알려 주세요 (선택) ── │
│ 관심사 [과학][게임][+]   [건너뛰기] │  ← 선택 7개 중 랜덤 2개
│ 가치관 (안정)(성장)(돈)…  [건너뛰기] │
│          [ 인생 시작하기 ]        │
└───────────────────────────────┘
```
- 동작: 필수 4개가 모두 차야 시작 버튼 활성. 선택 항목은 매번 7개 중 랜덤 2개 ([03 1-2](03-api.md#1-2-게임-시작))
- 입력 보기: 나이 정수 7~99, 지금 상황 · 관심사 · 가치관 보기와 최대 개수는 [03 1-2 표](03-api.md#1-2-게임-시작)
- 진행 중인 플레이가 있으면 **[이어하기]** 를 크게, **[새로 시작하기]** 를 작게 보여 준다. 새로 시작하면 확인 모달 "진행 중인 인생은 지난 기록에 남아요. 새 인생을 시작할까요?" 를 띄운다 (이전 플레이는 끝내지 않음)
- 상태: 시작 중 로딩 / 필수 값 누락 시 입력칸 아래 안내
- 관련 기능 #: FE1 · FE2 · FE8

### 화면 2: 게임 (`/play/:playId`)
```
┌──────────────────────────┬──────────┐
│ [나레이션] 15살 봄, …      │ 15세      │
│ [친구 민수] 뭔 소리야, …   │ 시간 ▓▓░  │
│ [나] 응 나 과학자임        │ 자금 ▓░░  │
│ …                         │ 건강 ▓▓▓  │
│ 힌트: (동아리에 대해 묻기)  │ 관계 ▓▓░  │
│ [ 입력…            ][보내기]│ 역량 ▓░░  │
└──────────────────────────┴──────────┘
```
- 동작: 입력 → 응답이 오면 메시지 추가, 바뀐 상태는 잠깐 강조 표시. 힌트를 누르면 입력칸에 채워진다
- 목표 상태 패널: 나이·자금(원화)·빚(0원도 표시)·건강·에너지·스트레스. 건강·에너지·스트레스는 0~100이며 자금을 0~100 막대로 해석하지 않는다. 주거·월 지출과 성적/자기계발은 해당 상황에서 표시한다. 관계는 인물별 화면에, 흥미와 NPC의 비공개 해석은 일반 패널에 노출하지 않는다. 상태와 변화 강조는 백엔드가 확정한 값만 사용한다. 현재 프론트 구현은 나이·자금·에너지 위주이며 이 목표 범위로의 확장은 후속 구현이다
- 3D 분기: 응답에 `experience` 가 있으면 대화 안에 **체험 안내 카드**를 보여 준다 — 체험 제목(`title`) · 관련 직업(`jobs`) · 이유(`reason`) + **[체험 시작]** · **[다음에 할게요]**. 없고 `notice` 가 있으면 토스트
  - [체험 시작] → 화면 3 으로 전환 (Unity 준비 후 화면 3 의 [체험 시작하기] 로 실제 시작 — 브라우저 소리 · 시작 규칙상 사용자 클릭이 한 번 더 필요)
  - [다음에 할게요] 또는 카드를 두고 계속 입력하면 체험을 하지 않은 것으로 보고 카드를 "다음에 하기로 했어요" 로 접는다. 다음 채팅은 평소대로 진행한다 (따로 API 를 부르지 않는다)
- 상태: 대기 중 입력 잠금 + "생각하는 중…", 30초 초과 · AI 실패 시 입력한 문장을 남긴 채 오류 안내
- 요청 ID: 보낼 때마다 `requestId`(UUID)를 붙인다. 실패한 문장을 **그대로 다시 보내면 같은 ID**, 문장을 고치거나 새 말을 하면 새 ID 를 쓴다 ([03 게임 상태와 턴 확장](03-api.md#게임-상태와-턴-확장-2026-10-31)). 응답을 못 받았다고 새 ID 로 자동 재전송하지 않는다
- 상태 반영: 턴 응답의 `state` 를 확정 값으로 쓴다 (`stateChanges` 는 강조할 항목을 고르는 데만 쓴다)
- 일시정지: 상태 패널 아래 [일시정지] 를 누르면 `PATCH /api/v1/plays/{playId}` `{paused:true}` → 입력칸을 잠그고 "일시정지 중이에요" + [이어 하기]. 다시 접속해도 재개 응답의 `paused` 로 유지한다
- 관련 기능 #: FE3 · FE4 · FE7

### 화면 3: 3D 체험 (게임 화면 위 전체 화면)
```
┌───────────────────────────────────┐
│ [Unity WebGL iframe]               │
│   (게임 안: 🔊 효과음 켜기)          │
│                                   │
│                [체험 종료하기]       │
└───────────────────────────────────┘
```
- 동작: Unity 준비 완료(`ready`) 후 **[체험 시작하기]** 를 눌러 시작. [체험 종료하기] → 종료 응답 · 저장 확인 후 텍스트 화면 복귀 ([4-1](#4-1-3d-체험-연결-unity))
- 종료 대기: 종료를 누르면 "체험 기록을 저장하는 중…" 을 보여 준다. 5초 안에 종료 응답이 없으면 미수신 기록을 보내고(03 1-10) "체험 기록 확인이 늦어지고 있어요. 텍스트로 이어갈게요." 토스트와 함께 텍스트로 돌아간다
- 상태: 로딩 표시 / 로딩 실패 토스트 / 체험 중 오류 모달 ([10 4-4](10-prompt-assembly.md#4-4-오류-안내-문구))
- 관련 기능 #: FE5 · FE6 · FE7

### 화면 4: 결말 (`/play/:playId/result`)
- 결말 요약, 경험한 직업 · 체험, 추천 직업 3개(카드)와 다음 준비 방향, [다른 인생 살아 보기]
- 추천 카드: 직업명 · 근거 표시(`basis` → "3D 체험함" · "대화에서 관심" · "흥미 기록" · "희망 직업") · 새 직업이면 "새로운 일" 표시(`isNew`) · 추천 이유 · 하는 일 · 다음 준비 방향
- 추천은 "적성 판정"이 아니라 이번 인생의 경험 기반 제안이라는 문구를 함께 보여 준다 ([10 7절 표현 원칙](10-prompt-assembly.md#7-결말--추천-직업-be12--ai5))
- 상태: 결말을 처음 만들 때는 AI 가 쓰는 동안 **"이번 인생을 정리하는 중…"** 로딩(카드 자리 skeleton). 30초 초과 · 실패 시 오류 문구 + [다시 시도]
- 관련 기능 #: FE9

## 4. API 호출 공통 모듈

| 항목 | 규칙 |
|------|------|
| 주소 | 백엔드 주소(터널 주소)는 환경변수(`VITE_API_BASE_URL` 등)로만 둔다. 코드에 직접 쓰지 않는다. 반드시 `https://` |
| 플레이어 ID | 첫 접속 때 받은 `playerId` 를 브라우저(localStorage)에 보관하고 모든 요청 헤더 `X-Player-Id` 로 보낸다 ([03 인증](03-api.md#인증-방식)) |
| CORS | **프론트는 따로 설정하지 않는다.** 허용은 백엔드(Django)가 한다 ([06 CORS](06-deployment.md#cors--django-가-담당)). 쿠키를 쓰지 않으므로 `credentials` 옵션도 쓰지 않는다. 프론트 배포 주소가 바뀌면 백엔드 담당에게 알린다 |
| 응답 처리 | `{code, data}` / `{code, error}` 를 한곳에서 풀고, `error.message` 를 화면 문구로 쓴다 ([03 결과 코드](03-api.md#결과-코드-목록)) |
| 채팅 대기 | 30초가 넘으면 `TIMEOUT` 안내 |

### 4-1. 3D 체험 연결 (Unity)
> Unity 연결 코드(`client.js`)는 `frontend/` 로 복사하지 않고, **빌드에 함께 들어 있는 `<buildUrl>/frontend/client.js` 를 실행할 때 불러와 쓴다** (`frontend/src/lib/experience/runtime.ts`). 빌드와 연결 코드의 버전이 항상 같아진다. 규칙 원문은 `docs/unity/frontend/` (원본 보관소). 파일 안내: [docs/unity/USAGE.md](../unity/USAGE.md)

| 항목 | 규칙 |
|------|------|
| 참고할 코드 | `Experience.jsx` (+ `client.js` · `backend.js` · `audio*.js` · `*.d.ts`) — 동작 · 메시지 형식 · 확인 규칙을 그대로 따른다 |
| `siteUrl` | 백엔드가 준 `buildUrl` + `index.html` |
| `manifest` | 같은 빌드의 허용 목록 `buildUrl + supported-manifest.json` 을 받아 넘긴다. 시작할 조합은 이 목록에서 `buildId` · `roomId` · `scenarioId` · `scenarioVersion` 네 값으로 찾는다 |
| `sessionId` | 플레이 동안 유지. 체험을 시작할 때마다 새 `experienceId` · `requestId` (UUID) |
| 시작 시점 | `onStatus` 가 `ready` 를 준 뒤 **사용자 버튼 클릭**으로 `client.start()` 한다. 렌더 · StrictMode effect 에서 자동 시작하지 않는다 |
| 백엔드 어댑터 | `createBackendAdapter({ eventEndpoint, reconcileEndpoint, heartbeatEndpoint, interruptionEndpoint, credentials: 'omit', headers: () => ({ 'X-Player-Id': playerId }) })`. **`credentials: 'omit'` 필수** — 기본값 `include` 는 쿠키를 보내 CORS 에서 막힌다 (우리는 쿠키를 쓰지 않음). 주소는 [03 1-4 · 1-8 · 1-9 · 1-10](03-api.md#1-4-3d-체험-이벤트-전달) |
| 전송 큐 | `createOutbox({ send: adapter.sendEvent })`. 백엔드가 `stored: true` 를 줄 때만 저장 성공 |
| 생존 신호 · 정산 | 체험 중 30초마다 `heartbeat`, 새 체험 시작 전 이전 체험 `reconcile`, 종료 5초 무응답 시 `markPending` |
| 종료 | 종료 응답을 받고 저장 확인까지 받은 뒤 iframe 을 제거한다 |
| 배경색 | `backgroundColor="#101e24"` (`--color-bg` 와 같은 값). prop 또는 `client.setPresentation({ backgroundColor })`. 불투명 6자리만. 페이지 바깥 배경은 CSS 로 따로 |
| 효과음 | 브라우저는 **iframe 안을 클릭해야** 소리를 켠다. 바깥 시작 버튼 클릭만으로는 보장되지 않으니 게임 화면 안의 효과음 켜기 버튼을 안내한다 |
| CSP | Vercel 에 CSP 를 설정한다면 `frame-src` 에 `https://*.trycloudflare.com` 을 허용한다. 함께 필요한 것: `connect-src` 에 `https://*.trycloudflare.com` (API · 3D 빌드의 `client.js` · `supported-manifest.json` · 인트로 에셋 `intro.json` · GLB), `script-src` 에 `https://*.trycloudflare.com` (빌드의 `client.js` 를 실행 시 불러옴), `style-src` · `font-src` 에 `https://cdn.jsdelivr.net` (Pretendard). 현재는 CSP 를 설정하지 않았다 |
| 주소 변경 | 백엔드 주소는 터널 주소라 바뀔 수 있다. 바뀌면 Vercel 환경변수만 바꾸고 재배포한다 ([06 터널 주소가 바뀌었을 때](06-deployment.md#터널-주소가-바뀌었을-때)) |

## 5. 결과 코드별 사용자 메시지
| code | 화면에 보여 줄 문구 | 동작 |
|------|---------------------|------|
| 400 `INVALID_INPUT` | 입력 내용을 다시 확인해 주세요. | 해당 입력칸 강조 |
| 401 `UNKNOWN_PLAYER` | 플레이 정보를 찾을 수 없어요. 처음부터 다시 시작해 주세요. | 게스트 ID 재발급 후 시작 화면 |
| 404 `NOT_FOUND` | 요청한 정보를 찾을 수 없어요. | 시작 화면으로 |
| 409 `ALREADY_ENDED` | 이미 끝난 진행이에요. | 결말 화면으로 |
| 409 `NOT_ENDED` | 아직 이야기가 끝나지 않았어요. | 게임 화면으로 |
| 409 `REQUEST_CONFLICT` | 같은 요청 ID의 입력이 다릅니다. | 입력 문장 유지. 다음 전송은 새 `requestId` |
| 409 `STATE_CONFLICT` | 최신 상태를 조회한 뒤 다시 시도해 주세요. | 입력 문장 유지, 플레이를 다시 조회(1-7)해 대화 · 상태를 최신으로 바꾼다 |
| 409 `PLAY_PAUSED` | 일시정지를 해제해 주세요. | 입력 문장 유지, 일시정지 상태로 표시 |
| 409 `TURN_IN_PROGRESS` | 같은 요청 ID를 유지하고 잠시 후 다시 시도해 주세요. | 입력 문장 유지, 다시 보내면 같은 `requestId` |
| 502 `AI_UNAVAILABLE` | 잠시 후 다시 시도해 주세요. | 입력 문장 유지, 다시 보내기 |
| 503 `CONTENT_UNAVAILABLE` | 가이드라인 준비가 필요합니다. (서버 문구) | 입력 문장 유지. 서버의 게임 문서 배치 문제라 운영자 확인 |
| 504 `TIMEOUT` | 응답이 늦어지고 있어요. 잠시 후 다시 시도해 주세요. | 입력 문장 유지, 다시 보내기 |
| 네트워크 오류 | 연결이 끊겼어요. 인터넷 연결을 확인해 주세요. | 다시 보내기 |

3D 관련 문구는 [10 4-4](10-prompt-assembly.md#4-4-오류-안내-문구).

## 6. 오류 메시지 원칙
- 무엇이 안 됐는지 + 사용자가 할 수 있는 일을 한 문장씩. 서버 내부 정보(스택, ID)는 보여 주지 않는다
- 사용자가 입력한 내용은 오류가 나도 지우지 않는다
- 브라우저 `alert` 는 쓰지 않는다. 진행을 막지 않으면 토스트, 진행이 끊기면 모달

## 8. SEO · 접근성
- 검색 노출은 필요 없다 (게임 화면). 페이지 제목 · 설명만 둔다
- 버튼 · 입력칸에 라벨, 키보드로 입력 · 전송(Enter) 가능. 한글 입력 중 Enter 중복 전송 방지
- 상태 막대는 숫자도 함께 표시 (색만으로 구분하지 않음)
- 인트로: [건너뛰기] 는 키보드로 바로 닿게 두고, 로딩 진행 문구는 `role="status"` 로 읽힌다. 움직임이 싫은 사용자를 위해 모션 줄이기 설정을 따른다

## 9. 상세 기획에 따른 상호작용

기획 기준: [인생·직업 상세 기획](../game/06-life-career-design.md). 아래는 후속 구현 범위다.

- NPC가 상황에 맞는 직업 기회를 먼저 제시하고 다른 직업 보기·직접 말하기·나중에 결정하기를 허용한다. 체험 뒤에는 느낌을 묻고 다음 준비 경로를 제안한다.
- 핵심 업무는 선택지와 자유 입력 모두 허용한다. 막히면 NPC가 힌트를 주고 결과를 짧게 피드백한다. 중요한 결과는 대화와 확정된 상태 변화로 보여 준다.
- 자금 부족 시 가능한 해결 방법을 선택하게 하고, 선택 전에 잔액·비용·빚에 미치는 영향을 알 수 있게 한다. 자동 대출로 넘기지 않는다.
- 일상 압축 뒤 경과 요약을 보여 주고 긴 기간 경과 전에는 계속할지 묻는다. 새로운 선택이 필요한 사건이 생기면 중간 시점에서 멈춘다.
- 일시정지·재개 동작을 제공한다. 화면 종료·백그라운드 구간을 활성 플레이 시간에 더하지 않고, 재개 시 마지막 확정 상태를 조회한다. AI 요청 대기는 무활동으로 오인하지 않는다.
- 네트워크 오류 재시도에는 동일 `requestId`를 유지한다. AI가 제안한 값을 먼저 화면 잔액에 반영하지 않는다. 비공개 NPC 기억은 클라이언트에 보내지 않는다.
