## 1. 역할 분담

**팀: 뽀스와아이들 (5명, 팀장 김정현)** — 출처: [해커톤정보.txt](../해커톤정보.txt)

| 이름 | 배경 | 맡은 역할 |
|------|------|-----------|
| 김정현 (팀장) | 디자인 전공 | Unity 3D 체험 개발 |
| 변승언 | 전자 · 컴퓨터공학, 스토리지 엔지니어 경력 | AI 서버 |
| 윤수현 | 컴퓨터공학, 마케팅 경력 | 백엔드 API |
| 이성준 | 컴퓨터공학, 프론트엔드 개발 경력 | 웹 프론트 · 문서 총괄 |
| 이지혜 | 보안 석사과정 (참여 제한적) | 시나리오 작가 |

| 역할 | 담당 | 담당 기능 # | 작업 위치 | 주요 산출물 |
|------|------|-------------|-----------|-------------|
| 문서 총괄 | 이성준 | — | `docs/` (`docs` 브랜치) | 설계 문서 · 결정 기록 |
| 백엔드 | 윤수현 | BE1 ~ BE14 | `backend/` | Django API · DB · 서버 배포 |
| 웹 프론트 | 이성준 | FE1 ~ FE11 | `frontend/` | 화면 · Unity 연동 · Vercel 배포 |
| AI 서버 | 변승언 | AI1 ~ AI5 | 별도 저장소 | Qwen + RAG API · GPU 서버 배포 |
| Unity 3D 체험 | 김정현 | — | Unity 담당 저장소 → `docs/unity/` 로 전달 | WebGL 빌드 · 연동 명세 · 카탈로그 · 인트로 소스와 3D 모델 (FE11 원본) |
| 시나리오 작가 | 이지혜 | — | `docs/game/` | 가이드라인 · 시나리오 · 규칙(게임 상태 필드) · NPC |

> 라벨 · 커밋 scope: 백엔드 · AI 작업은 `be`, 프론트는 `fe`.

**의존 관계 / 순서**
1. API 문서([03](03-api.md)) 확정 → 백엔드 · 프론트 · AI 가 동시에 시작 (프론트는 API 예시로 목업 진행)
2. 백엔드가 정한 `docs/game/` 파일 틀에 시나리오 작가가 가이드라인 · 시나리오 · 규칙 첫 판 작성 → 백엔드 프롬프트 조립(BE3 · BE4) · AI 응답 검증(L6)
3. AI 서버 대화 생성(AI1) → 백엔드 채팅 턴(BE4) 실제 연결
4. 백엔드 이벤트 저장(BE8) → 프론트 3D 연동(FE5 · FE6) → Unity 새 빌드로 통합 확인
5. 결말 · 추천(BE12 · FE9) → 전체 플레이 · 시연 준비
