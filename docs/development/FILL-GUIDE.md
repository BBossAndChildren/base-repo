# 문서 채우기 가이드 (AI 용 지시서)

> 이 폴더(`docs/development/`)의 문서들은 **개발 설계 문서의 빈 뼈대**다. 아이디어 문서([`docs/00-idea.md`](../00-idea.md))를 기준으로 AI 가 순서대로 채운다.
> 시작 프롬프트 예: "`docs/development/FILL-GUIDE.md` 를 읽고, `docs/00-idea.md` 를 기준으로 개발 문서를 채워 줘. 모호한 건 질문해."
>
> **폴더 구분**: 개발 설계(기능·API·DB·화면·배포)는 `docs/development/`, 게임 콘텐츠(세계관·게임 시나리오·규칙·AI 프롬프트 기록)는 [`docs/game/`](../game/README.md), 협업 규칙은 [`docs/CONTRIBUTING.md`](../CONTRIBUTING.md). 게임 콘텐츠를 이 폴더에 쓰지 않는다.

## 0. 가장 먼저 알아 둘 것 — 뼈대는 출발점일 뿐이다

- 이 뼈대는 **다른 프로젝트(웹 서비스)에서 쓰던 문서 구성을 일반화한 것**이다. 지금 프로젝트에 그대로 맞는다는 보장이 없다.
- **아이디어에 맞게 문서를 추가 · 삭제 · 이름 변경 · 합치기 · 나누기 해도 된다.** 오히려 그래야 한다.
  - 예: 화면이 없는 서비스면 `05-ui-ux.md` 삭제, 외부 연동이 많으면 `02` 에서 연동 문서를 따로 분리, 배치 작업이 핵심이면 `작업 스케줄` 문서 추가
  - 문서 안의 절(섹션)도 마찬가지 — 필요 없는 절은 지우고, 필요한 절은 만든다
- 뼈대에 있는 **표 형식 · 기록 방식 · 문서 간 링크 규칙**은 최대한 유지한다. 이 형식들이 이 뼈대의 핵심 가치다.
- 문서 구성을 바꾸면:
  1. 이 가이드의 [2. 문서 목록과 채우는 순서](#2-문서-목록과-채우는-순서) 표를 실제 구성에 맞게 고친다
  2. 다른 문서의 링크가 깨지지 않게 함께 고친다
  3. 바꾼 이유를 `12-decisions.md` 에 한 줄 이상 남긴다 (예: "UI 가 없는 CLI 도구라 05 를 삭제")
- 문서 구성 변경을 시작하기 전에 **어떤 문서를 추가·삭제·변경할지 사용자에게 먼저 제안하고 확인받는다.**

## 1. 채우기 규칙

| 규칙 | 내용 |
|------|------|
| 기준 문서 | `00-idea.md` (사용자 아이디어) → `features.md` (기능 번호) 순으로 기준이 된다. 뒤 문서는 앞 문서와 모순되면 안 된다 |
| 기능 번호 | 기능마다 번호를 붙인다 (예: 백엔드 `B1`, 프론트 `F1`). 다른 문서는 이 번호로 기능을 가리킨다 |
| 지어내지 않기 | 아이디어에 없는 값(숫자·정책·외부 서비스)은 임의로 정하지 않는다. **추천안 + 이유**를 적고 `11-open-issues.md` 에 "미확정"으로 올려 사용자에게 묻는다 |
| 결정 기록 | 정한 것은 `12-decisions.md` 에 **결정 → 근거 → 버린 대안 → 한계** 형식으로 남긴다 |
| 확정 이동 | `11` 의 미확정 항목이 결정되면 관련 문서를 고치고 `11` 의 "0. 확정" 표로 옮긴다 |
| 민감정보 | API 키 · 비밀번호 값은 어디에도 쓰지 않는다. 환경변수 **키 이름**만 적는다 |
| 안내 주석 | `<!-- -->` 안내는 채운 뒤 지운다. 아직 못 채운 곳은 `TODO:` 로 남긴다 |
| 링크 | 다른 문서를 언급할 때는 `[03-api.md 1-1. 회원가입](03-api.md#1-1-회원가입)` 처럼 절 단위로 링크한다 |

- 한 번에 전부 채우지 말고 **2~3개 문서씩 채우고 사용자 확인**을 받는다. 특히 `features.md` 와 `03-api.md` 는 확정 후 다음으로 넘어간다
- 협업 규칙(브랜치·커밋·PR)은 `docs/CONTRIBUTING.md` 에 있다. 여기 문서에 다시 쓰지 않는다
- 게임 콘텐츠와 연결되는 기능(예: AI 프롬프트를 쓰는 API)은 `docs/game/` 의 해당 문서로 링크만 건다

## 3. 구현 중 문서 갱신

- API · DB · 화면이 바뀌면 **같은 PR 에서** 해당 문서를 고친다
- 결정이 바뀌면 `12` 에 갱신 사유를 추가한다 (이전 결정을 지우지 말고 "변경" 으로 남김)
- 문서와 코드가 다른 걸 발견하면 `11` 의 "E. 코드와 문서 차이" 에 올린다
