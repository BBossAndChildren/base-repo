## 1. 서비스 정의

사용자의 현재 나이와 상황에서 출발해 일상 속 사람과 사건을 만나고, 대화와 행동을 통해 직업과 미래의 가능성을 탐색하는 AI 시뮬레이션 게임이다. 현재 대한민국의 시대적 상황을 배경으로 하며, 사용자는 원하는 직업을 향한 준비 과정을 탐색하거나 아직 생각해 보지 못한 일을 경험할 수 있다.

80억 분의 1의 인생 시뮬레이션과 문명의 전략·성장 시스템을 참고한다. 플레이어는 한 사람의 삶에서 공부, 취미, 인간관계, 사업, 직업과 도전을 경험하며, 각 결정은 능력·자원·관계·기회·미래 사건에 영향을 준다. 역량을 성장시키고 새로운 분야를 개척하면서 자신의 삶을 전략적으로 설계한다.

서비스의 핵심 가치는 **경험을 통해 관심을 발견하고, 관심 있는 일의 실제 업무와 필요한 준비를 이해하며 스스로 미래를 선택하도록 돕는 것**이다. 게임 속 사건과 인물은 가상이며, 직업을 설명할 때는 직업백과 데이터를 근거로 활용한다.

## 2. 해결하려는 문제

“우리 아이가 나중에 뭘 하고 싶냐는 질문에 ‘하고 싶은 게 없어’라고 대답한다면 어떻게 해야 할까?”

이 질문이 기획의 출발점이다. 세상에 다양한 직업과 삶의 방식이 있어도 아직 충분히 접하지 못했다면 원하는 일을 말하기 어려울 수 있다. 그때 “그럼 이 게임 한번 해볼래?”라고 권할 수 있는 경험을 만들고자 한다. 성인도 자신이 무엇을 좋아하는지 모르거나 다른 직업을 알아보고 싶을 수 있다.

진로를 고민하는 사람은 직업 이름을 알아도 실제로 무슨 일을 하는지, 어떤 역량과 준비 과정이 필요한지 자신의 상황에 연결해 이해하기 어려울 수 있다. 하고 싶은 일이 없는 경우에는 다양한 일을 접할 기회가 부족해 무엇부터 탐색해야 할지 막막할 수 있다.

이 서비스는 일상 속 대화, 우연한 만남, 중요한 결정과 직업 체험을 통해 직업 세계를 접할 기회를 제공한다. 사용자가 궁금해하는 일과 경험 중 드러난 관심을 바탕으로 다음 탐색과 준비 방향을 제안한다.

이 문제 정의는 현재의 기획 가설이다. 실제 수요와 진로 탐색 효과는 검증되지 않았다.

## 3. 핵심 철학과 목표

**게임이 먼저고, 진로 탐색은 그 안에서 자연스럽게 이루어져야 한다.** 교육적으로 유익하더라도 재미가 없다면 사용자가 지속하기 어렵다는 문제의식에서 출발한다. 재미있기 때문에 자발적으로 플레이하고, 그 과정에서 새로운 직업과 자신의 흥미를 발견하는 경험을 지향한다.

하나의 정답이나 성공적인 인생을 정해두지 않는다. 부자가 되거나 명문대에 진학하는 것이 유일한 승리 조건은 아니다. 연구, 창작, 사업, 다른 사람을 돕는 삶 등 다양한 가치관과 경로를 존중한다.

게임의 목표는 **다양한 인생을 경험하며 자신이 원하는 삶과 일을 발견하는 것**이다. 실패도 경험의 일부이며 모든 플레이가 성공으로 끝날 필요는 없다.

## 4. 희망 직업 유무에 따른 탐색

### 희망 직업이 있는 경우

사용자가 현재 상황에서 그 직업을 향해 어떤 경험과 준비를 할 수 있는지 탐색한다. 관련 인물을 만나 질문하고, 업무를 경험하고, 직업백과의 업무·역량·준비 정보를 바탕으로 길을 알아가는 방식이다. 사용자가 목표를 말하는 것만으로 게임 속 직업을 즉시 획득하지 않는다.

### 희망 직업이 없는 경우

직업을 미리 고르지 않고 일상에서 출발한다. 주변인의 제안과 외부 사건을 통해 여러 활동과 일을 접하고, 대화와 경험 속에서 관심을 발견한다. 사용자의 반응과 관심에 따라 관련 직업이나 다음 경험을 제안하는 방향이다.

## 5. 진행 속도와 인생 전략

### 빠른 템포

**한 번의 인생 플레이는 최대 15분**으로 설계한다. 짧은 시간에 여러 결정과 결과를 경험하고 다른 인생에 다시 도전할 수 있게 한다.

나이에 따라 배정한 시간 단위로 인생이 흘러간다. 할 수 있는 활동이 적은 어린 시기는 빠르게 지나가고, 핵심인 직업 체험에는 상대적으로 더 긴 시간을 배정한다. 평범한 기간은 텍스트로 압축하고, 중요한 기회·갈등·직업 체험에서는 3D로 직접 개입한다. 나이별 시간 배분과 15분 안의 상세한 진행 규칙은 추가로 정해야 한다.

### 인생 전략 모드

- 나이와 시간 경과에 따라 학업·취미·인간관계를 선택한다.
- 역량과 자원을 성장시키고 새로운 분야와 직업을 해금한다.
- 예상하지 못한 사건을 만나며 장기적인 결정의 결과를 확인한다.

현재 구체적인 설명이 있는 모드는 인생 전략 모드다. 직업 체험은 주요 플레이 요소로 포함하며, 별도의 두 번째 모드 구성과 명칭은 정하지 않았다.

### 나이에 따른 경험 예시

다음은 진행 방식의 이해를 돕는 예시이며 필수 경로나 시연 계획이 아니다. 여기서 ‘선택’은 자유 텍스트로 표현한 결정도 포함한다.

| 나이 예시 | 경험 예시                                               |
| --------- | ------------------------------------------------------- |
| 10세      | 과학 실험에 흥미를 느낀다.                              |
| 13세      | 과학 동아리에서 연구 프로젝트를 시작한다.               |
| 16세      | 연구대회 참가와 게임 개발 중 어떤 활동을 할지 결정한다. |
| 20세      | 대학 진학·창업·취업·다른 진로 탐색을 고려한다.          |
| 25세      | 연구원으로 연구 프로젝트를 수행한다.                    |
| 30세      | 새로운 분야로 전환하거나 기존 전문성을 발전시킨다.      |

사용자의 현재 나이와 상황에서 시작한다는 원칙을 유지하며, 모든 플레이가 어린 시절부터 시작할 필요는 없다.

## 6. 일상과 자유 텍스트 상호작용

사용자는 자신의 말로 대화하거나 행동을 표현한다. 게임은 현재 상황, 이전 경험, 등장인물과의 관계를 바탕으로 그 입력에 반응한다.

- **질문:** 상대가 알고 있는 정보와 상황에 맞춰 답한다.
- **수락·거절:** 사용자의 의사를 반영한다. 거절한 사건을 수락한 것으로 처리하지 않는다.
- **관심 표현:** 새로운 대화나 경험을 연결할 단서로 활용한다. 한 번의 발언만으로 적성이나 희망 직업을 확정하지 않는다.
- **상황과 다른 주장:** 사용자의 발언과 확인된 사실을 구분한다. 학생인 사용자가 ‘나 과학자야’라고 말해도 실제 직업으로 자동 저장하지 않는다.

사용자가 예상과 다른 말을 하더라도 일상과 이야기를 이어갈 수 있어야 한다. 자유로운 입력과 큰 이야기 흐름을 함께 유지하는 것이 설계 원칙이며, 시간 경과·분기·종료의 상세 규칙은 아직 정하지 않았다.

## 7. 주변 인물과 랜덤성

**주변 인물의 페르소나, 직업, 사용자에게 미치는 영향 등을 랜덤으로 구성한다.** 가족, 친구, 주변 직업인과의 관계 속에서 새로운 기회와 이야기가 생기는 방식이다. 랜덤 구성은 사용자 상황과 대화 맥락에 맞아야 한다.

| 인물 요소      | 서비스에서의 의미                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------ |
| 페르소나       | 성격과 말투에 따라 같은 말에도 다르게 반응한다.                                                  |
| 직업           | 인물이 소개할 수 있는 일과 경험의 범위에 영향을 준다.                                            |
| 관계           | 가족·친구·처음 만난 사람 등 사용자와의 관계에 맞게 행동한다.                                     |
| 알고 있는 사실 | 직접 들었거나 경험한 내용을 바탕으로 반응한다. 다른 인물만 아는 정보를 자동으로 공유하지 않는다. |
| 미치는 영향    | 사용자가 접하는 제안·활동·직업과 이후의 경험에 영향을 준다.                                      |

랜덤 생성 시점과 범위, 인물 수, 관계와 기억의 변화 규칙은 추가로 정해야 한다.

## 8. 텍스트와 3D의 역할

**평소에는 텍스트로 일상과 대화를 진행하고, 중요한 인생 분기와 상세한 직업 체험에서는 3D로 진행한다.** 다음 항목은 3D를 적용할 주요 분기 종류로 정리한 것이다. 모든 사용자가 전부 거쳐야 하는 필수 경로는 아니다.

| 주요 분기                   | 다루려는 결정 또는 경험                        |
| --------------------------- | ---------------------------------------------- |
| 고등학교·대학교 입학        | 진학과 관련된 결정                             |
| 직업 결정·직업 체험         | 일을 선택하고 실제 업무를 상세히 경험하는 상황 |
| 군대                        | 군 복무와 관련된 인생 분기                     |
| 결혼·출산                   | 가족 형성과 관련된 인생 분기                   |
| 사업 결정·사업 진행         | 사업을 시작하고 운영하는 과정                  |
| 유학                        | 해외에서 공부하는 선택과 경험                  |
| 워킹홀리데이·해외 직업 체험 | 해외에서 생활하고 일하는 경험                  |

특정 직업이나 활동에 진입하면 AI가 실제 직무정보를 바탕으로 상황과 문제를 생성하는 방향이다. 플레이어는 가상 동료와 협력하고 직접 조작하거나 문제를 해결하며 결과를 경험한다. 짧고 몰입감 있는 미니게임으로 업무의 특징을 표현한다.

| 직업 예시 | 체험 활동 예시                                 |
| --------- | ---------------------------------------------- |
| 연구원    | 실험을 설계하고 예상하지 못한 결과에 대응한다. |
| 개발자    | 오류를 찾고 해결한다.                          |
| 사업가    | 상품을 판매하고 고객의 요청에 대응한다.        |

이는 체험의 방향을 설명하는 예시다. 구체적인 3D 상호작용, 미니게임 규칙과 각 분기의 상세 콘텐츠는 추가 설계가 필요하다. AI가 상황을 생성하는 범위와 미리 제작하는 콘텐츠의 경계도 정해야 한다.

### 직업 체험 범위 (회의 결정)

- **직업별로 물건 3개와 상호작용하는 체험으로 제한한다.** 반복 이벤트를 넣거나 직업 수를 늘리는 방향은 범위가 커져 추가하지 않는다.
- **3D 체험의 선택과 성과를 기록한다.** 체험 중 사용자가 무엇을 했고 성공했는지를 결과값으로 남기고, 메인 인생 시뮬레이션의 평가와 이후 사건에 반영한다. 결과값은 Unity → 웹 프론트 → 백엔드 순서로 전달한다.

## 9. 성장·자원과 재미

### 핵심 자원

능력치를 지나치게 세분화하지 않고 다음 요소를 관리한다.

| 자원        | 역할                                         |
| ----------- | -------------------------------------------- |
| 시간        | 모든 활동에 필요한 제한 자원                 |
| 자금        | 학습·생활·사업 등에 사용하는 자원            |
| 건강·에너지 | 활동을 지속하고 회복하는 데 영향을 주는 요소 |
| 관계        | 협력·기회·갈등에 영향을 주는 요소            |
| 역량        | 실제 활동 경험을 통해 성장하는 능력          |

**흥미는 역량과 분리한다.** 잘하는 일과 좋아하는 일이 같다고 단정하지 않으며, 좋아하는 일을 처음부터 잘할 필요도 없다. 각 자원의 초기값·소모·회복·성장 수식은 아직 정하지 않았다.

### 재미를 만드는 요소

- **빠른 결정과 즉각적인 반응:** 행동의 결과가 눈에 보이게 나타난다.
- **예상하지 못한 사건:** 첫 고객의 큰 주문, 연구 중 뜻밖의 결과 등으로 새로운 대응을 요구한다.
- **결정의 연쇄 효과:** 어린 시절이나 이전에 경험한 활동이 나중의 기회로 연결된다.
- **여러 전략과 결말:** 돈, 연구, 창작, 사회적 기여 등 서로 다른 삶의 방향을 탐색한다.
- **직접 해결하는 체험:** 짧은 미니게임과 업무 상호작용으로 조작과 문제 해결을 경험한다.
- **재도전과 수집:** 발견한 직업·사건·경험을 기록하며 다른 경로를 탐험할 동기를 제공한다.

### 반복 플레이

한 번의 인생으로 모든 것을 경험하지 않는다. 첫 플레이에서는 과학자의 길을 걷고, 다음에는 사업이나 예술을 시도할 수 있다. 같은 직업이어도 출발 환경과 행동에 따라 다른 이야기가 진행된다.

실패와 다른 결말도 다시 도전할 이유가 된다. “이번에는 다른 인생을 살아볼까?”라고 느낄 수 있는 짧은 반복 구조를 지향한다. 기록의 저장 범위와 다음 플레이에 이어지는 요소는 추가로 정해야 한다.

## 10. 직업 정보와 추천

**직업백과 데이터를 사용하며 파인튜닝은 하지 않는다.** 직업명, 하는 일, 핵심 능력과 준비 방법을 대화·직업 체험·준비 방향 안내의 근거로 활용한다. NCS는 사용하지 않는 방향으로 정리했다.

추천은 사용자가 표현한 목표와 관심, 경험한 활동을 바탕으로 관련 직업과 다음 경험·준비 방향을 제안하는 역할이다. 구체적인 추천 시점, 판단 기준과 결과 표현 방식은 아직 정해야 한다.

가상 이야기와 실제 직업 정보를 구분한다. 준비 경로를 안내할 때 확인된 자료를 사용하고, 게임의 결과를 실제 취업이나 진로의 보장으로 제시하지 않는다. 직업백과 자료의 서비스 이용·모델 전송·재배포 조건은 별도로 확인해야 한다.

## 11. AI의 역할과 게임 규칙

AI는 자유 입력의 의미와 상황을 해석하고, 인물에 맞는 대사와 후속 상황을 만드는 데 사용한다. 현재 장면, 이전 대화와 경험, 인물의 페르소나·관계·지식을 함께 고려해야 한다.

자유도에는 게임 규칙을 둔다. 범죄, 폭력, 자해·자살 및 가족을 해치는 행동 등 허용하지 않을 행동과 위기 표현에 대한 대응 기준이 필요하다는 방향을 정했다. 금지 범위와 구체적인 반응은 추가로 정의해야 한다. 가족과의 의견 충돌이나 정당한 거절까지 자동으로 금지하는 식으로 해석하지 않는다.

모델 지침과 함께 서버가 게임 상태와 허용된 진행을 확인하는 구조를 검토하고 있다. 실제 상태 검증과 모델의 지침 준수는 아직 구현·검증이 필요한 사항이다.

### 시나리오와 가이드라인 (회의 결정)

- **시나리오는 AI 지침 중심으로 작성한다.** 모든 인생 경로를 고정 대본으로 만들지 않고, 게임 흐름과 NPC가 따라야 할 공통 규칙을 문서로 만든다. 사용자가 범위를 크게 벗어나면 NPC가 흐름을 되돌린다.
- **시나리오·가이드라인 문서는 시나리오 작가가 마크다운으로 작성한다.** 백엔드는 이 문서들을 갖고 있다가 **매 AI 요청마다 고정으로 프롬프트에 넣는다.**
- **가이드라인 문서는 반드시 둔다.** 자살·자해 시도, 법을 위반하는 행동 같은 선택을 막고, 사용자의 말만으로 직업 등 플레이어 상태를 바꾸는 응답(예: 갑자기 "직업이 과학자로 바뀌었다")을 하지 않도록 규칙을 적는다.

## 12. 제공 방식과 3D 공간 제작

Unity를 활용하고 웹으로 제공하는 방향이다. 웹 빌드 용량이 부담되면 앱으로 전환하는 방안을 고려한다. 전환 기준은 실제 빌드의 용량과 실행 결과를 보고 정해야 한다.

### 서비스 구조 (회의 결정)

웹 프론트 · 백엔드 · AI 서버 세 부분으로 나눈다.

| 구성 | 역할 |
| --- | --- |
| 웹 프론트 | 웹 화면에서 텍스트로 AI와 채팅하며 게임을 진행한다. 3D가 필요한 분기에서는 백엔드가 보내 준 Unity WebGL 빌드를 렌더링하고, 체험 결과값을 백엔드로 보낸다. |
| 백엔드 | 게임 상태·플레이어 정보를 관리한다. 시나리오·가이드라인 마크다운을 매 요청마다 프롬프트에 넣어 AI 서버에 요청한다. Unity WebGL 빌드 파일들과, 빌드와 그 빌드에서 쓰는 에셋을 설명하는 정보 JSON을 갖고 있다. |
| AI 서버 | 백엔드가 보낸 프롬프트로 대화·상황을 생성하고, 3D 분기에서는 정보 JSON을 보고 상황에 맞는 빌드와 에셋을 추천한다. |

**빌드 단위:** 빌드는 직업 하나가 아니라 **환경 콘셉트마다** 하나씩 만든다. 예를 들어 사무직·연구직처럼 사무실에서 일하는 직업은 사무실 콘셉트 빌드를, 공사 인부는 야외 공사 현장 콘셉트 빌드를 쓴다. 같은 빌드 안에서는 상황에 따라 에셋만 달라진다 (예: 보라색 사무실·주황색 사무실, 상호작용하는 물건).

3D 체험 흐름:

1. 텍스트 모드로 진행하다가 3D가 필요한 분기에 도달한다.
2. 백엔드가 빌드·에셋 정보 JSON을 정리해 AI 서버에 보내고, 상황에 맞는 빌드와 에셋을 추천해 달라고 요청한다.
3. AI 서버는 추천한 빌드와 에셋을 돌려준다.
4. 백엔드는 추천받은 **빌드 파일 자체**와 에셋 정보를 그대로 프론트에 보낸다.
5. 프론트는 받은 빌드를 받은 에셋 정보대로 렌더링하고 3D 체험을 진행한다.
6. 체험이 끝나면 결과값(선택·성과)을 백엔드에 보내고, 백엔드는 이를 프롬프트에 담아 텍스트 모드를 이어 간다.

- **맞는 빌드가 없거나 AI가 정보 JSON에 없는 빌드·에셋을 돌려주면** 3D를 건너뛰고 텍스트로 계속 진행한다. 안내는 브라우저 `alert` 창을 쓰지 않고 모달이나 토스트로 보여 준다.

직업별 근무장소 후보 분류를 바탕으로 **Meshy AI로 사무실 3D 공간을 만들어 보기로 했다.** 공간을 재사용하면서 직업과 상황에 맞는 경험을 구성하는 방향이다. 근무장소 분류에는 자동 분류와 추정이 포함돼 있어 해당 직업의 업무와 공간이 맞는지 확인해야 한다. 실제 생성 결과와 게임 적용 여부는 아직 검증되지 않았다.

## 13. 추가로 구체화할 사항

- 주변 인물의 랜덤 생성 기준, 관계와 기억 관리 규칙.
- 최대 15분 안에서 자유 입력과 직업 체험을 배분하는 나이별 시간·분기·종료 규칙.
- 시간·자금·건강·에너지·관계·역량의 초기값과 변화 기준, 흥미를 별도로 기록하는 방식.
- 모드 구성의 추가 여부, 반복 플레이의 기록과 수집 범위.
- 직업별 물건 3개의 구체적인 상호작용, 기록할 성과 항목과 메인 시뮬레이션에 반영하는 방식.
- 빌드·에셋 정보 JSON의 항목 구성, 만들 환경 콘셉트 빌드의 종류와 수.
- 관심과 경험을 추천으로 연결하는 판단 기준과 안내 방식.
- 중요한 인생 분기의 상세 콘텐츠와 3D 전환 조건.
- 허용하지 않을 행동과 위기 표현의 세부 대응 기준.
- 직업백과 데이터 이용 조건, 3D 자산의 용량과 실행 성능
- 과거 회귀(내가 어렸을 때의 시대로 돌아가서 사용자가 정한 나이로부터 시작)

반응 예시
실제 상황: 중3, 친구는 플레이어가 학생인 것을 안다.
사용자: “응 나 과학자임.”
AI 친구 반응 예: “뭔 소리야, 너 학생이잖아. 과학자가 되고 싶다는 거야?”
서버: 발화는 기록한다. 단지 말한 것만으로 플레이어의 실제 직업을 과학자로 변경하지 않는다.
새로 만난 연구원이 같은 말을 들으면 플레이어의 실제 신분을 모를 수 있다. 캐릭터가 모르는 사실을 단정해 반응하지 않도록 정보를 구분한다.

플레이어의 행동을 강제로 성공시키지 않으며, 근거 없는 상태 변경도 자동 확정하지 않는다. 비꼬는 말투는 관계·상황에 맞는 예시일 뿐 모든 NPC의 기본 말투가 아니다.
